## Files and fields

- `dev.jsonl`, `test.jsonl`: one case per line, ids `qa-00001` … `qa-10000` in source order (raw batches 01-40, then the top-up). Fields: `id`, `locale`, `role`, `persona` (case type), `message`, `expectedFaqId` (null = no FAQ answers it), optional `acceptableFaqIds`, `conversationId` + `turn` for multi-turn, optional `note`, and `origin` (raw batch file and raw id, or `merge-topup#gen-NNN`). No case sets `source`, so all are chat cases.
- FAQ ids refer to `faqs.json` in this folder (35 FAQs: the 14 seed FAQs plus 21 grounded in Portal copy), not `../faqs.json`. Run with `--faqs server/eval/helpdesk/qa10k/faqs.json` (or the CLI equivalent).
- The harness scores every turn on its own; it has no conversation history. Later turns that lean on context ("then how do I cancel it myself?") are still labelled with the FAQ that answers them.
- `role` is the learner profile the batch wrote the case for; synonyms from different batches were mapped to one name (e.g. `parent_guardian` -> `parent`, `new_learner` -> `new_student`).

## Split

Deterministic: units are conversations (all turns together) or single cases. Units are grouped by stratum (locale x persona x answerable/null of the first turn), ordered by SHA-256 of their normalised text, and dealt to whichever split is behind in that stratum; 0 single-case units were then moved to make the totals exactly 50/50. No conversation spans both files.

## Known limits

- Labels were written by the batch generators, spot-checked by the merge step and by the label audit above, not reviewed line by line; expect a small share of debatable labels outside the reviewed groups.
- Follow-up turns are labelled in context, but the harness scores each turn alone (see `byTurn` in the reports).
- zh-TW cases (many in Cantonese) are matched against Simplified-Chinese FAQ text. Production retrieval now converts Traditional to Simplified and rewrites Cantonese and regional words (2026-10-29). Dev retrieval-only recall@8 for zh-TW went from 72.2% to 95.0% (`lg-helpdesk/qa10k/retrieval-dev-before.md` / `retrieval-dev-after.md`). Retrieval was tuned on dev only; test was measured once afterwards.
- Pinyin-only messages (zh-CN typo cases such as `wangji mima`) and Chinese homophone typos (密吗, 视屏) still have no lexical match.
- Batch 37 was not in the generation report list but its file is in raw/ and passed validation, so it is included.
