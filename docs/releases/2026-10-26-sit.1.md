## 1. 一页速览

本次为 Admin BackOffice Portal 首次 SIT 发布。SIT 此前没有 BackOffice，下列能力均为首次上线：员工登录、员工账号管理、六角色权限、中英文切换与偏好记忆、邮件通知，并将 BackOffice、Knowledge、AI Tutor 收进同一后台入口。

**测试重点**

1. 登录、激活、忘记密码、重置密码、改密全链路。
2. 员工账号列表、搜索筛选分页、新建/编辑/停用/重发激活/重置密码。
3. 六角色菜单可见性与 View/Edit/Full 操作边界。
4. 中英文切换、语言与侧栏折叠跨登录保留。
5. 邮件投递结果、一次性链接复制，以及过期/已用链接的提示。

**不在本次范围**

- Course、Order、Reporting、Student、HelpDesk 功能页；Settings 下 Payment Gateway、Notification Configuration 功能页。
- BackOffice 之外的 AI Tutor RAG、课程同步改造、引擎拆分。
- 自助注册、社交登录、密码复杂度策略、邮件模板自定义。
- P1/P2 功能。

## 4. 部署与升级

### 4.1 数据库迁移

本次 BackOffice 新增 2 个迁移，按顺序执行：

1. `20261023150000_backoffice_employees` — 员工、会话、一次性令牌、审计、UI 偏好、后台设置；仅新增表，不改旧表。
2. `20261023170000_backoffice_default_admin` — 仅在 `employees` 为空时插入受保护管理员 `admin@ilovelearningguide.com`；不覆盖已有员工。

> 范围外提醒：如果 SIT 按 `dev` 整体部署，还会执行 `20261024090000_ai_rate_limit_hits` 与 `20261026000000_add_knowledge_chunk`；后者需要 pgvector。本文不展开这两个模块的功能。

### 4.2 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `APP_ENV` | 是 | 设为 `SIT`；影响邮件链接、环境判定和调试便利 |
| `NODE_ENV` | 是 | 生产构建设为 `production`；会话 Cookie 会启用 Secure，SIT 必须使用 HTTPS |
| `DATABASE_URL` | 是 | SIT 数据库连接串 |
| `BACKOFFICE_APP_URL` | 是 | SIT 后台站点根地址；不配或配错时，邮件链接可能回退到生产域名 |
| `AUTH_TOKEN` | 是 | `/api/user/**` 服务密钥与 `/api/auth/setup` 校验；生产环境未配置时 setup 会被拒绝 |
| `SESSION_SECRET` | 建议 | 至少 32 字符；不配则首次启动生成并存入数据库；多实例必须共用 |
| `BOOTSTRAP_ADMIN_EMAIL` / `BOOTSTRAP_ADMIN_PASSWORD` | 可选 | 仅当 SIT 库没有员工时创建首个管理员；已有员工则忽略 |
| `SMTP_HOST` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | 二选一 | SMTP 投递；163 示例为 `smtp.163.com:465` |
| `SES_FROM_EMAIL` / `AWS_REGION` | 二选一 | SES 投递；SIT 若在 sandbox，只能发到已验证地址 |
| `EMAIL_DELIVERY` | 可选 | `discard` / `fail`，仅联调用 |
| `APP_ROLES` | 可选 | 本次按单服务部署，留空即 admin、agent、ks 同进程 |
| `CLIENT_DIST_DIR` | 可选 | 前端构建产物路径；默认 `client/dist` |
| `PGSSL` / `PGSSL_STRICT` | 可选 | SIT RDS 强制 TLS 时的连接控制；默认非本地连接会加密 |
| `PORT` | 可选 | 默认 3000 |

### 4.3 发布前预检

- 确认 SIT 后台域名与 HTTPS 证书可用；HTTP 下 Secure Cookie 不会生效。
- 备份或快照 SIT 数据库；确认执行迁移的账号有建表、建触发器和写入默认管理员的权限。
- 确认 SIT RDS 的连接方式：若强制 SSL，检查连接串与 `PGSSL` / `PGSSL_STRICT`；原生 SQL 连接默认对非本地地址启用加密。
- 确认 `BACKOFFICE_APP_URL` 指向 SIT 域名，末尾不要带多余路径。
- 确认 `AUTH_TOKEN` 已配置；确认 `SESSION_SECRET` 已配置或允许数据库持久化。
- 确认邮件服务：SMTP 可用，或 SES 已退出 sandbox/已添加测试收件地址；未配置时只能使用一次性链接。
- 查询 SIT 库 `employees` 数量：为空则默认管理员会被插入；已有员工则默认管理员不会插入，需要走 bootstrap 或 setup。
- 如果 SIT 库来自旧独立 Next.js 原型，先确认旧表结构与新迁移兼容；员工表迁移使用 `IF NOT EXISTS`，不会自动修正旧表差异。
- 如果按 `dev` 整体部署，额外确认 pgvector 扩展权限和 embedding 所需配置；否则只需关注 BackOffice 两个迁移。

### 4.4 发布步骤

1. 安装依赖并构建前端、后端；确认 `client/dist` 与 `server/dist` 均存在。
2. 执行 `npx prisma migrate deploy`，确认两个 BackOffice 迁移成功。
3. 启动服务；单服务部署时 `APP_ROLES` 留空。
4. 检查 `/api/health` 返回 200，确认服务版本与环境正确。
5. 按 4.5 完成冒烟后再通知测试。

### 4.5 发布后冒烟

- `/api/health` 返回 200。
- `/en-GB/sign-in`、`/zh-CN/sign-in` 正常加载。
- 使用默认管理员或 bootstrap 管理员登录成功。
- 员工账号列表正常加载；搜索、筛选、分页可用。
- 新建一个测试员工，确认邮件发送结果与一次性链接。
- 使用测试员工激活并登录；停用后确认会话立即失效。
- 非 Admin 直接访问 `/settings/employee-account`，确认显示无权。
- 切换中英文并退出再登录，确认语言与侧栏折叠状态保留。
- 从统一入口打开 Knowledge、AI Tutor，确认按角色显示或隐藏。
- 如 SIT 同批部署 Portal 学员端，回归 `/api/user/**` 的 `X-API-Key` 调用。

## 5. 影响范围与兼容性

- **访问控制**：除公开的登录、激活、忘记/重置密码、健康检查等接口外，`/api/**` 现在按员工会话与菜单权限放行；`/api/user/**` 仍走 `X-API-Key`；`/api/ks/**` 为内部接口。
- **页面入口**：Knowledge、AI Tutor 收进 BackOffice 统一外壳，未登录会跳转登录页；旧书签缺少语言前缀时会补默认语言并重定向。
- **静态资源**：前端由同一服务托管；`client/dist` 必须随构建产物存在，非 API 的 GET/HEAD 返回 `index.html`，深链接可直接刷新；缺少前端产物时服务只提供 API。
- **数据**：新增员工、会话、一次性令牌、审计、UI 偏好、后台设置表；均为新增表，不修改旧表字段；默认管理员迁移会插入一条员工记录。
- **邮件**：激活链接 48 小时、重置链接 2 小时，均为单次使用；管理员触发的创建、重发、重置即使邮件发送成功也会返回一次性链接，便于人工转交。
- **角色**：六角色按菜单与 View/Edit/Full 判定；员工账号仅 Admin 可访问；视觉设计的 Course=Edit 落到 Knowledge=EDIT；运营管理员的 Knowledge、AI Tutor 保持不可见。
- **会话**：Cookie 为 httpOnly、SameSite=Lax，生产环境 Secure；绝对超时 7 天（168 小时）、空闲超时 7 天（10080 分钟）；停用账号立即吊销会话。
- **兼容**：旧独立 Next.js 原型的数据库如被复用，需要先确认表结构与新迁移一致；否则建议使用干净的 SIT 库。
- **接口契约**：BackOffice 不改变 Portal 学员端接口的请求/响应格式；但所有 Admin 页面与接口现在依赖员工登录态。

| 低 | 限制 | 管理员触发的创建/重发/重置在邮件发送成功后仍显示一次性链接 | 设计如此，便于人工转交；不是链接泄露；自助忘记密码不返回链接 |

| 低 | 限制 | 员工列表 UI 默认每页 8 条，服务端上限 100 | 与设计稿一致；切换每页条数会记忆 |

## 7. 回退方案

### 7.1 触发条件

出现以下任一情况，停止扩大验证并评估回退：

- 登录、激活或重置密码主链路不可用。
- 员工账号列表或新建/编辑/停用不可用。
- 迁移失败，或数据库出现不可恢复的结构问题。
- 统一入口导致 Knowledge、AI Tutor 无法打开，且无法快速修复。

### 7.2 回退动作

- **代码**：重新部署 `main` 当前稳定基线（commit 见附录 10.1）或 App Runner 上一个成功部署。首次 SIT 回退到 `main` 意味着 BackOffice 整体下线，测试和产品需同步知晓。
- **配置**：回退本次新增或修改的环境变量；保持 `SESSION_SECRET` 稳定，避免全员会话失效；保留 `BACKOFFICE_APP_URL` 的正确值，避免邮件链接回退生产。
- **数据**：迁移为 forward-only，不执行 down；新增表可以保留。若迁移中途失败或数据异常，使用发布前的 RDS 快照恢复；恢复后重新执行迁移。
- **邮件**：如邮件配置导致阻塞，可先切换到手动一次性链接，不阻塞账号激活与重置。
- **验证**：回退后检查 `/api/health`、登录页、员工列表、Knowledge/AI Tutor 入口和 Portal 学员端接口。

### 7.3 回退后的通知

- 通知测试、产品和运维当前 SIT 版本与可用范围。
- 明确 BackOffice 是否整体下线，避免测试继续提交无效缺陷。
- 记录回退原因、影响范围和后续修复计划。

#### BackOffice 相关变更

1. **会话有效期调整为 7 天**：空闲超时与绝对超时统一为 7 天（`SESSION_MAX_DAYS = 7`），除非主动签出或清理 Cookie，7 天内无需重新登录；对应 `securityPolicy.ts` 与本文第 5 节。
