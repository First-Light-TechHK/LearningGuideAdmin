- 详情：The only runtime role in the stack (`AppRole`, `learning-guide-sandbox-runtime`) grants `secretsmanager:GetSecretValue` restricted to `secret:learning-guide/sandbox/*` (line 181). App Runner startup fails to resolve those RuntimeEnvironmentSecrets, so the services never become healthy.

### HIGH · Set-Cookie host-only check is broken: `.size` on an Array is undefined, and the probed page is a 307 redirect that sets no cookie

- 位置：`scripts/sandbox-smoke.mjs:60`
- 详情：`assertHostOnlyCookies` is passed `home.response.headers.getSetCookie?.() ?? []` (line 119). Per the Fetch spec (verified locally with Node: `Array.isArray(...) === true`, `len===1`, `size===undefined`), `getSetCookie()` returns an **Array<string>**, not a Map. The aggregate assertion therefore evaluates `cookies.size > 0` where `cookies.size` is `undefined`, so `record('cookie:'+label, ...)` always records `fail` (and prints `undefined`) even when Set-Cookie headers exist and are host-only (lines 70-72). Separately, the probe fetches `${portal}/` (line 117) expecting status 200, but the Portal root is `redirect("/en-GB/portal")` (`LearningGuidePortal/app/page.tsx:4`), which returns a 307; with `redirect: "manual"` (line 52) the smoke sees 307, so `portal:home:200` also fails and there are no cookies to inspect anyway.
- 失败场景：On a healthy Portal, fetching `/` yields a 307 to `/en-GB/portal` with no Set-Cookie; the smoke records `portal:home:200` failure and `cookie:portal` failure. Even if a cookie were present, the `.size`-on-Array bug guarantees the host-only check reports failure, so this isolation evidence can never pass.
- 证据：Local Node check confirms `Headers.getSetCookie()` returns Array<string> (isArray true, len 1, `.size` undefined, `.entries()` yields [0,val]). sandbox-smoke.mjs:119 passes that array to assertHostOnlyCookies; line 62 iterates `cookies.entries()` (works on arrays) but line 70 evaluates `cookies.size > 0` = `undefined > 0` = false, so it always records `cookie:portal` as fail regardless of actual cookies. Separately, LearningGuidePortal/app/page.tsx:4 is `redirect("/en-GB/portal")` (a 3xx, not 200, no Set-Cookie), and the smoke uses `redirect:"manual"` (line 52) and asserts `home.response.status === 200` (line 118), so `portal:home:200` also fails. Only minor nit: line 70 prints the else-branch text `未观察到 Set-Cookie`, not literally `undefined`; the `.size` bug and 307 behavior are otherwise exact.
